## Task 2 — Lock the type and test setup [done]

- **Strict TypeScript.** The `react-ts` template shipped *no* `strict` in either project config, so `"strict": true` was added to both `tsconfig.app.json` and `tsconfig.node.json`. Also added to the app config: `noUncheckedSideEffectImports` and `noImplicitOverride`. Verified each one bites by compiling throwaway probe files and deleting them: an unannotated parameter fails with TS7006, `string | null` into a `string` return fails with TS2322, bare `this` fails with TS2683, and `import './x.zzz'` fails with TS2882. The existing `src/` (App, main, index.css) typechecks and builds unchanged under strict.
- **`any` is now a lint error.** The template uses **oxlint**, not ESLint (there is no ESLint config in the repo), so "ban explicit `any` in ESLint" was read as "ban explicit `any` in the template's linter". `.oxlintrc.json` now sets `"typescript/no-explicit-any": "error"`, plus `"typescript/ban-ts-comment": "error"` to cover the Decisions row that also bans `@ts-ignore`.
- **Vitest wired up in Node mode.** `vitest@5.0.2` was already in `package.json`/the lockfile from the interrupted run; the install was complete (`node_modules/vitest` present, peer range `^6.4.0 || ^7.0.0 || ^8.0.0` satisfied by the installed Vite 8, no duplicate nested Vite). Added `"test": "vitest run"`, which runs and exits — no watch mode. The test block lives in the existing `vite.config.ts` (importing `defineConfig` from `vitest/config`) rather than in a new config file, so tests inherit the `@` → `src` alias for free. Config: `environment: 'node'`, `globals: false`, `include: ['src/**/*.test.ts']`. No jsdom, no setup file, no DOM matchers; tests import `describe`/`it`/`expect` from `vitest`.
- **Temporary smoke test** at `src/smoke.test.ts` (2 tests): asserts `window` is undefined (Node, not jsdom) and that `@/App` resolves through the alias inside a test. The PRD says to delete it in task 3 if it no longer applies, so it is intentionally still present.
