## Task 3 — Define the board types [done]

- **`src/domain/types.ts`** (new) holds the whole board vocabulary in one module, so the UI and the rules read the same numbers: `BOARD_VERSION`, `DAY_START_MINUTE` (360), `DAY_END_MINUTE` (1320), `DRAG_SNAP_MINUTES` (15), `TYPED_STEP_MINUTES` (5), `MIN_ACTIVITY_MINUTES` (15), `MIN_TRAVEL_MINUTES` (5), `MIN_WORK_MINUTES` (15), `MAX_NAME_LENGTH` (40), and the `DAYS` tuple with `DayId` derived from it. No `Date` anywhere; a time is a number of minutes from midnight.
- Object shapes are `interface`s: `TravelMinutes`, `WorkInterval`, `DayPlan`, `TimeGoal`, `CountGoal`, `Session`, `OneOff`, `Board`. Closed sets are string unions: `DayId`, `ColorId`, `RefusalReason`, plus `Goal = TimeGoal | CountGoal` discriminated on `kind` and `Result<T>`. `Board.version` is `typeof BOARD_VERSION`, so the literal is `1` and a stored `version: 2` will not typecheck. No `any`, no `as any`, no `@ts-ignore`, no `enum` (`erasableSyntaxOnly` would reject one anyway).
- **`Result<T>` and `RefusalReason` live in `types.ts`, not `refusal.ts`.** Every mutation module (tasks 8–15) returns a `Result` and needs the reason union, so keeping both with the other closed sets beats a second import for each. The plan's architecture comment for `refusal.ts` was updated to "sentences for the reason codes in types.ts" so the tree matches the code. `refusalMessage` is still task 13's job and has not been written.
- **`src/domain/types.test.ts`** (new, 11 tests) pins the numbers the rest of the plan is written against, including `DAY_END_MINUTE - DAY_START_MINUTE === 960`, which is the column height task 12's geometry percentages are taken from. The two closed sets are locked at compile time by a `switch` that must return on every branch, and `Goal` is exercised through its `kind` discriminant so a count goal is proven to carry no minutes quota.
- **Deleted `src/smoke.test.ts`.** Task 2 left it to be deleted in task 3 "if it no longer applies"; `types.test.ts` now proves the same two things for real (it runs a `.test.ts` file and resolves the `@` alias, since it imports through `@/domain/types`), and its Node-environment assertion only restated a config value.
- **Every type-level guard was proven to bite**, not just to compile, by mutating a copy and running `tsc -b --force`: adding a 13th `ColorId` fails with TS2366, adding a 13th `RefusalReason` fails with TS2366, dropping `tuesday` from a `Record<DayId, DayPlan>` fails with TS2741, writing `version: 2` fails with TS2322, and `const probe: any = 1` in `types.ts` fails lint with exit 1. All probes were reverted and the tree re-checked clean.
- **Verified:** `npm test` exits 0 (1 file, 11 tests passed), `npm run lint` exits 0 (0 warnings, 0 errors over 5 files), `npm run build` exits 0 (`tsc -b`, then a minified `dist/`). `docs/product-scope.md` untouched.
